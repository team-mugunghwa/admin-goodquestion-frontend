# 디자인 시스템

토큰 코드: `lib/core/theme/` · `lib/core/constants/app_icons.dart`

여기 없는 값이 필요하면 **임의로 만들지 말고 이 문서에 추가한 뒤** 쓰세요.

---

## 1. 이 화면이 어떻게 생겨야 하는가

서비스 앱과 **같은 브랜드 색에서 출발하되 쓰임이 다릅니다.**

서비스 앱은 아이가 보는 화면이라 파스텔 면이 넓게 깔립니다. 관리자 콘솔은
**표와 숫자를 오래 들여다보는 화면**입니다. 색이 넓게 깔리면 정작 봐야 할
상태 배지와 숫자가 묻힙니다.

### 규칙 세 가지

1. **면은 흰색과 회색뿐입니다.** 브랜드 색은 주 버튼, 선택된 메뉴, 링크에만.
2. **상태는 색 하나로 말하지 않습니다.** 배지에는 색과 글자를 함께 둡니다 —
   표를 흑백으로 출력하거나 색각 이상이 있어도 읽혀야 합니다.
3. **빨강은 되돌릴 수 없는 것에만.** 삭제, 정지, 미답변 경고. 그 외에는 쓰지 않습니다.

### 하지 않는 것

- 지표 카드에 증감률 화살표 — 표본이 작을 때 요동이 심해(사용자 100명이면 3명
  차이가 3%) 판단을 오히려 흐립니다. 추세는 그래프가 보여줍니다
- 저장 전 확인 대화상자 — 저장은 되돌릴 수 있습니다. 확인 창이 늘어날수록
  정작 위험한 것에서도 그냥 누르게 됩니다
- 다크 모드 — 표와 배지가 화면의 대부분이라 두 벌을 검수할 여력이 없습니다

## 2. 색

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `primary` | `#2A6E9E` | 주 버튼, 선택된 메뉴, 포커스 링. 흰 배경 대비 5.5:1 |
| `primarySurface` | `#EAF3F9` | 선택된 행, 정보 배너 |
| `success` | `#387C4C` | 완료, 정상 |
| `warning` | `#9A6412` | 확인 필요, 초안 |
| `danger` | `#B3403C` | 삭제, 정지 |

**잉크(글자·선)** `ink900` 본문 · `ink700` 부제 · `ink500` 캡션 ·
`ink400` 비활성 · `ink300` 입력 테두리 · `ink100` 구분선

순수 검정을 쓰지 않습니다. 파랑기가 도는 남색이 회색 배경에서 덜 딱딱합니다.

**바탕** `canvas #F6F8FA` 화면 · `surface #FFFFFF` 카드 ·
`surfaceMuted #F0F3F7` 표 헤더·호버 · `navSurface #16233F` 좌측 메뉴

좌측 메뉴가 화면에서 유일하게 어두운 면입니다. 콘텐츠 영역과 경계를 확실히
나눠서 폭이 넓은 모니터에서도 눈이 길을 잃지 않게 합니다.

### 상태 배지의 색은 `StatusTone` 으로만 정합니다

뜻이 아니라 **강도**로 이름을 붙였습니다(`info`/`positive`/`caution`/
`negative`/`neutral`). 각 화면이 뜻을 이 다섯 중 하나로 번역하고, 색은
`AppStatusChip` 한 곳에서 정합니다. 그래야 "공개"가 어느 화면에서는 초록이고
다른 화면에서는 파랑이 되는 일이 없습니다.

## 3. 글자

**폰트를 번들하지 않습니다.** 서비스 앱은 두 벌을 싣지만, 관리자 콘솔은 운영자
몇 명이 데스크톱 브라우저로만 보는 화면입니다. 폰트 파일을 받아 오느라 첫 화면이
늦어지는 대가가 얻는 것보다 큽니다. 시스템 폰트 스택을 지정해 macOS·Windows
어느 쪽에서도 한글이 또렷하게 나오게 합니다.

| 토큰 | 크기/굵기 | 쓰는 곳 |
| --- | --- | --- |
| `pageTitle` | 24 / 700 | 화면 제목. 화면당 한 번 |
| `metric` | 30 / 700 | 대시보드 지표 숫자 |
| `sectionTitle` | 16 / 700 | 카드 제목 |
| `body` | 14 / 400 | 본문, 표 셀 |
| `bodyStrong` | 14 / 600 | 표의 첫 열, 버튼 |
| `tableHeader` | 12 / 600 | 표 헤더 |
| `caption` | 12 / 400 | 날짜, 보조 설명 |

`metric` 과 `number` 는 **고정폭 숫자**(`tabularFigures`)를 씁니다. 표에서 자릿수가
흔들리면 열이 지저분해 보입니다.

## 4. 간격 · 모서리 · 크기

**간격** `xs 4 · sm 8 · md 12 · lg 16 · xl 24 · xxl 32 · xxxl 48`
화면 좌우 여백은 `page`(32).

**모서리** `sm 6 · md 10 · lg 14 · pill 999`
입력·버튼·배지는 `md`, 카드·대화상자는 `lg`. **한 화면에서 2종류를 넘기지 마세요.**

**고정 크기** 좌측 메뉴 240 · 상단 바 64 · 표 한 행 52 · 클릭 타겟 40 ·
편집 폼 최대 폭 720 · 아이콘 20(표·버튼) / 24(강조)

## 5. 컴포넌트

새 컴포넌트를 만들기 전에 `lib/core/widgets/` 에 있는지 먼저 보세요.

| 위젯 | 하는 일 |
| --- | --- |
| `AdminShell` | 좌측 메뉴 + 상단 바. 로그인 이후 모든 화면을 감쌉니다 |
| `AppPage` | 제목 + 설명 + 우측 조작 + 본문 |
| `AppCard` | 흰 카드. 표·폼·지표를 담는 기본 그릇 |
| `AppDataTable` / `AppPagedTable` | 목록 표 (+ 페이지네이션) |
| `AppStatusChip` | 상태 배지 |
| `AppStateView` | 로딩 / 오류 / 빈 상태를 한 방식으로 |
| `AppField` / `AppSearchField` / `AppFilterBar` / `AppFilterDropdown` | 폼과 필터 |
| `showConfirmDialog` / `showPromptDialog` / `showResultSnackBar` | 확인·입력·결과 |

### 표를 직접 만든 이유

Flutter 의 `DataTable` 은 열 폭이 내용에 따라 정해져서 **페이지를 넘길 때마다
열 경계가 흔들립니다.** 같은 표를 여러 페이지에 걸쳐 훑는 관리자 화면에서는
그 흔들림이 계속 눈에 걸립니다. `AppColumn.flex` / `width` 로 폭을 고정합니다.

### 차트 라이브러리를 넣지 않은 이유

필요한 것은 막대 14개와 값 하나뿐인데, 차트 패키지는 축·범례·애니메이션·
인터랙션을 함께 가져오고 웹 번들이 그만큼 커집니다. `Column` 과 `Container` 로
충분합니다.

### 확인 대화상자는 되돌릴 수 없는 것에만

삭제, 정지, 로그인 세션 종료. **저장에는 쓰지 마세요** — 저장은 되돌릴 수 있고,
매번 확인을 받으면 사람이 내용을 읽지 않고 누르게 됩니다.

## 6. 문구

- 버튼 이름과 결과가 같은 말이어야 합니다. `저장` 을 눌렀으면 `저장했습니다`
- 막을 때는 **왜 막았고 대신 무엇을 할 수 있는지** 적습니다
  - 나쁨: "삭제할 수 없습니다"
  - 좋음: "이미 진행된 기록이 있어 삭제할 수 없습니다. 노출만 멈추려면 보관으로 바꾸세요"
- 조작이 사용자에게 보이면 그 사실을 적습니다
  - "저장하면 사용자 앱의 공지 목록에 바로 보입니다"
  - "답변 등록하고 알림 보내기"

## 7. 접근성 — 화면마다 확인

- [ ] 본문 대비 4.5:1 이상
- [ ] 색만으로 뜻을 전달하지 않는가 (상태 = 색 + 글자)
- [ ] 아이콘 버튼에 `tooltip` 이 있는가
- [ ] 1100px 이하로 줄여도 표의 열이 잘리지 않는가
- [ ] 키보드만으로 폼을 채우고 저장할 수 있는가 (검색·비밀번호는 엔터로 제출)
